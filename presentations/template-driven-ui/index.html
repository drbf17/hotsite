Artesanal

Jornadas Customizadas

Construídas do zero, para um único produto. Cada tela, cada regra de negócio e cada integração são desenhadas e codificadas sob medida.

Indicado para produtos de altíssimo volume ou extrema especificidade, onde o CAPEX se justifica pelo retorno exclusivo de uma solução dedicada.

  • Codebase dedicada por produto, sem reaproveitamento estrutural
  • Ciclo completo de design e desenvolvimento sob medida
  • Custo de manutenção e evolução mais alto ao longo do tempo
Ponto de Equilíbrio

Templates Low Code

O balanço perfeito entre velocidade de entrega e adequação ao produto. A jornada é montada a partir de componentes configuráveis do design system, com espaço para lógica e integrações específicas.

Indicado para a maioria das jornadas transacionais — onde previsibilidade de prazo importa tanto quanto aderência ao produto.

  • Motor de renderização + schema de configuração (JSON/YAML)
  • Componentes do design system parametrizáveis por produto
  • Integração facilitada com sistemas legados via SDK/API
Escala Máxima

Templates No Code

Não demanda desenvolvimento de software — apenas parametrização e cadastro do produto em uma plataforma corporativa já madura.

Indicado para escala. Onde o gargalo de crescimento não pode ser o time de engenharia.

  • Motor de orquestração self-service, sem deploy por produto
  • Depende de sistemas corporativos já adaptados e maduros
  • Time to market medido em horas, não em sprints

Um novo restaurante no iFood. Uma nova loja no Mercado Livre. Nenhuma linha de código nova — apenas cadastro.

O Jeito Certo

O jeito certo de fazer Template Driven UI

Template Driven UI não é sinônimo de telas monolíticas, presas a uma biblioteca comum e com baixa flexibilidade — isso é exatamente o gargalo de desenvolvimento que essa arquitetura deveria eliminar.

  1. ✕ ✓

    Templates engessados, que não permitem ativar ou desativar campos, telas e opções conforme a jornada.

    Templates flexíveis, que permitem ativar e desativar campos, telas e opções para cada jornada específica.

  2. ✕ ✓

    Templates presos a uma biblioteca do app, com forte uso de módulos nativos — toda mudança exige atualização na loja.

    Templates atualizados over the air (OTA), sem depender do ciclo de publicação nas lojas.

  3. ✕ ✓

    Templates tratados como componentes de tela inteira, mantidos em uma biblioteca de design system.

    Templates tratados como meta-jornadas, que recebem dados de configuração — incluindo endpoints de BFF — e realmente minimizam o esforço de desenvolvimento.

  4. ✕ ✓

    Telas e jornadas planejadas por áreas distantes do dia a dia do produto, de forma autoritária.

    Equipe dedicada a ouvir as necessidades dos times de produto e identificar oportunidades de templatização.

  5. ✕ ✓

    Evoluções no template forçando ajustes constantes nas jornadas, fora do ritmo dos times de produto.

    Templates versionados, com contratos imutáveis e roadmap claro de suporte: quebrar o contrato exige uma nova versão, com convivência entre versões por um prazo bem definido.

  6. ✕ ✓

    Templates pouco genéricos, feitos sob medida para um único produto — não trazem ganho de escala e ainda transformam a biblioteca de templates em gargalo.

    Templates com o nível certo de generalização, reutilizados de verdade em várias jornadas.

Roadmap

Do quick win ao norte estratégico

Duas fases, uma trajetória. Começamos pelo ganho rápido e evoluímos para a escala máxima.

01
Comece aqui

Low Code — o primeiro passo

A implementação mais rápida dentro do ciclo de vida do projeto. Nossa vitória de curto prazo: menos estrutura pesada de backend, resultado tangível já nos primeiros ciclos.

Ciclo
Planejar → Configurar → Testar → Lançar
  • Requer menos investimento inicial em motores de renderização dedicados
  • Minimiza a necessidade imediata de múltiplos middlewares complexos
  • Aproveita a base de design system e infraestrutura já existentes
02
Onde queremos chegar

No Code — a visão de futuro

O norte estratégico da arquitetura. Uma fase futura porque exige uma fundação técnica mais robusta — mas que devolve escala praticamente ilimitada.

Ciclo
Cadastrar → Validar → Lançar
  • Motor de renderização dinâmico, orientado a schema
  • Middlewares orquestradores de backend (BFF) dedicados
  • Infraestrutura avançada de armazenamento e gerenciamento de estado/configuração
  • Governança e versionamento dos templates publicados
Especificação Técnica

Como funciona a Fase 1

Módulos federados entregam os templates, produtos os configuram por contrato, o BFF traduz para os sistemas corporativos — uma arquitetura pensada desde o início para evoluir até o No Code, sem retrabalho.

  1. 1

    Módulos federados, carregados over the air, expõem os templates prontos para a implementação das jornadas.

  2. 2

    Módulos de produto consomem os templates informando dados de configuração, seguindo um contrato definido e imutável. Quebras de contrato geram novas versões do template, convivendo em paralelo com as anteriores.

  3. 3

    Os templates recebem os endpoints da jornada concreta, sem acoplamento a nenhum produto específico.

  4. 4

    Os BFFs atuam como Facade: expõem para a jornada templatizada o contrato padrão do template e ficam responsáveis por acessar as APIs corporativas, mapeando os dados.

  5. 5

    Uma base pronta para evoluir de forma incremental até a Fase 2 — No Code.

Antes de fechar

Os três modelos são complementares, não excludentes

Cada um atende melhor a um tipo específico de jornada — a escolha certa depende do produto, não de uma preferência única.

Produtos que exigem uma jornada verdadeiramente customizada e têm estrutura própria para mantê-la.

Jornadas Customizadas Ex.: envio de Pix.

Produtos com jornadas que compartilham elementos com as de outros produtos, mas dependem de integração com sistemas corporativos legados.

Templates Low Code Ex.: contratação de Seguro de Vida e de Cartão de Crédito adicional.

Produtos com jornadas análogas, que podem operar sob um único sistema de gestão.

Templates No Code Ex.: lojas de varejo ou restaurantes em um marketplace.
Posicionamento

Template Driven UI não economiza linhas de código. Multiplica a capacidade de gerar valor — sem multiplicar o time.

Cada jornada que hoje nasce do zero é uma jornada que amanhã poderia nascer configurada. A pergunta não é se vamos adotar Template Driven UI — é quantas oportunidades de negócio vamos deixar na mesa até decidirmos começar.
